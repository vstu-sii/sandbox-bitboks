# Где врём: отчёт по первому прогону evals

Прогон baseline по golden dataset v2 (40 диалогов записи, переноса и отмены),
5 октября 2026. Разбор — по типам ошибок, а не по средней метрике: средняя
точность 82% ничего не говорит о том, где студенту больно.

Приоритет — по боли для студента: что будет, если ошибка случится у него.

## 1. Выдумывает свободные даты — приоритет 1

- **Сколько:** 3 из 40.
- **Пример:** студент: «на неделе с 12-го есть что-то у Ланит?» — бот:
  «да, 14 октября свободно». В таблице кафедры у Ланит 14-го ничего нет.
- **Боль:** высокая. Студент придёт к партнёру на дату, которой нет, —
  потерянный день и испорченное впечатление о партнёре.
- **Что делаем:** даты только из БД, модель их не генерирует (требования v2).

## 2. Путает направление — приоритет 2

- **Сколько:** 5 из 40.
- **Пример:** «хочу в аналитику, но с данными» — бот отнёс к «данным» и
  показал партнёров по ML-инженерии.
- **Боль:** средняя. Студент видит не тех партнёров, но замечает это сразу
  и может переписать.
- **Что делаем:** переспрос с кнопками при неуверенности (UC-01, 2а).

## 3. Переспрашивает дважды — приоритет 3

- **Сколько:** 2 из 40.
- **Пример:** студент назвал группу в первом сообщении, бот всё равно
  спросил её на шаге 5 — и потом ещё раз.
- **Боль:** низкая. Раздражает, но до записи студент доходит. Нарушает
  ADR-0003 — поэтому в списке.

## 4. Не понимает сокращения групп

- **Сколько:** 4 из 40.
- **Пример:** «ПрИн-366» бот не узнал как группу и переспросил.
